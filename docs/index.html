AK Base Kit

Nền firmware bare-metal cho STM32L151, dựng trên kernel AK Active Object: các task giao tiếp qua message, chạy hết việc mới nhường (run-to-completion), không cần RTOS. Có sẵn bootloader, cập nhật firmware không cần ST-Link, và build bằng một lệnh. Kit trên trang này đang chạy thật: đó là chính mã C của firmware, biên dịch sang WebAssembly.

01Tổng quan

Repo gồm hai phần: ak-mcu-base (bản viết lại, tách khỏi chip, có unit test; dự án mới bắt đầu từ đây) và base cũ trong legacy/ (dành cho dự án đang chạy trên nó). Cả hai cùng dựa trên kernel AK.

KERNEL

Không cần RTOS

Task giao tiếp bằng message, chạy hết việc mới nhường. Tốn ít RAM, không có race giữa các task.

BOOT

Bootloader có sẵn

Kiểm ảnh trước khi chạy, cài bản mới từ flash ngoài, tự cứu khi app hỏng.

02Kernel AK hoạt động thế nào

Mỗi task là một active object: có hàng đợi message riêng, chỉ xử lý một message mỗi lần. Ngắt (ISR) không làm việc nặng, chỉ post message rồi thoát. Scheduler luôn chọn task có ưu tiên cao nhất đang có message.

ISR / task

Có sự kiện (ngắt UART, hết giờ timer, task khác gửi) → task_post_*()

Message pool

Lấy message từ pool tĩnh (pure / common / dynamic), không malloc trong ISR

Hàng đợi ưu tiên

8 mức ưu tiên, mỗi task một hàng đợi FIFO

Run-to-completion

Gọi handler của task, chạy xong mới lấy message tiếp; giải phóng message

Viết một task

/* task_list.h — thứ tự enum phải khớp bảng */
enum {
    TASK_TIMER_TICK_ID,
    TASK_SYSTEM_ID,
    TASK_SENSOR_ID,      /* task mới */
    AK_TASK_EOT_ID,
};

/* task_list.c */
task_t app_task_table[] = {
  {TASK_TIMER_TICK_ID, TASK_PRI_LEVEL_7, task_timer_tick},
  {TASK_SYSTEM_ID,     TASK_PRI_LEVEL_2, task_system},
  {TASK_SENSOR_ID,     TASK_PRI_LEVEL_3, task_sensor},
  {AK_TASK_EOT_ID,     TASK_PRI_LEVEL_0, (pf_task)0},
};
/* task_sensor.c */
void task_sensor(ak_msg_t* msg) {
    switch (msg->sig) {
    case SENSOR_SIG_INIT:
        /* đọc cảm biến mỗi 500 ms */
        timer_set(TASK_SENSOR_ID, SENSOR_SIG_READ,
                  500, TIMER_PERIODIC);
        break;

    case SENSOR_SIG_READ: {
        uint8_t v = sensor_read();
        task_post_common_msg(TASK_SYSTEM_ID,
                  SYSTEM_SIG_DATA, &v, 1);
    }   break;
    }
}

Kernel tra task theo chỉ số task_table[id], nên dòng thứ n phải mang id = n. Lệch thứ tự thì FATAL("TK", 0x08) ngay lúc khởi động, thay vì để message đi nhầm task.

DÒNG LỆNH

Python

Kiểm ảnh trước khi gửi, tự xác nhận phiên bản sau khi board khởi động lại.

python -m epcb_applib.ota COMx \
  legacy/release/app_mbslave/ak_base_kit_app_mbslave_v1.3.0.bin \
  --slave 1 --baud 9600
Chỉ gửi ảnh build từ app_mbslave. Ảnh của env app vẫn qua được bước kiểm nhưng không có task Modbus slave: nạp xong board mất đường OTA, phải quay lại dùng ST-Link.

Dùng cho dự án mới

  1. Clone theo tag v1.3.0, xoá .git, git init, ghi "Khởi tạo từ ak-base-kit-pio v1.3.0" vào README.
  2. Đổi định danh trong platformio.ini: APP_TITLE, APP_VERSION, build_dir, prefix tên file release.
  3. Chọn module bằng cờ: TASK_MBMASTER_EN / TASK_MBSLAVE_EN / SERIAL2_EN (USART2 chỉ một chủ), OLED, link UART…
  4. Sửa phần cứng theo schematic mới: io_cfg.h/.c, sys_cfg.c.
  5. Build thử cả hai env: 0 lỗi, 0 cảnh báo; nạp boot + app, console lên log, LED nháy.
  6. Viết chức năng theo mô hình AK: thêm task ID + dòng trong bảng task đúng vị trí, tạo app/task_xxx.cpp.
  7. Release: tăng APP_VERSION, build, lấy file trong release/.

MẤT ĐIỆN

Header ghi sau cùng

Trang header của APP bị xóa đầu tiên và chép cuối cùng. Mất điện ở bất kỳ bước nào thì APP luôn "không hợp lệ", lần boot sau tự chép lại từ STAGING.

AN TOÀN

Kiểm đủ trước khi chạy

CRC32 của header và ảnh, tên board (chống nạp nhầm board), địa chỉ nạp, bảng vector. App không ghi được vào chính nó hay vào bootloader.

TỐC ĐỘ

Ghi half-page

Khối 128 B được ghi trong một lần thay vì 32 lần, bằng hàm chạy từ RAM. Header nằm sẵn trong .elf, nạp bằng SWD vẫn boot được.

Chạy thử ngay trên máy tính

cd ak-mcu-base
make test       # unit test + test OTA đầu-cuối trên trình giả lập
make sim        # chạy bootloader + app giả lập: gõ 'help' trong shell
make stm32      # build/stm32l151/{boot.bin, app.img, *.elf}

# nạp firmware qua UART console (board thật hoặc trình giả lập)
python3 tools/ak_fw.py --port /dev/ttyUSB0 flash build/stm32l151/app.img
python3 tools/ak_fw.py --sim build/host/ak_sim info
